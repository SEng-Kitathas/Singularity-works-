# Additive Doctrine Addendum — Linear Human Read / Semantic Gate

Date: 2026-09-03
Authority source: explicit operator directive
Scope: Main-Dev / Forge project-local process doctrine
Relationship to RAHL R4.1: additive local overlay; does not rewrite the sealed R4.1 source package.

## Exact binding

**LINEAR HUMAN READ / SEMANTIC GATE**

> If an artifact can be meaningfully read, it SHALL receive a complete linear semantic read before it is promoted, sealed, published, admitted, or treated as load-bearing. Automated checks may precede and support the gate; they SHALL NOT substitute for it.

## Operational effect
- The gate applies before promotion, sealing, publication, admission, or load-bearing treatment.
- Automated verification, hashing, manifests, tests, hostile suites, parsers, scanners, linters, or other machine checks may support the gate but do not discharge the human semantic-read obligation when the artifact can be meaningfully read.
- This is an additive project-local control law and therefore survives thread changes through the Git-backed project-control checkpoint.

## Non-substitution laws
`AUTOMATED_CHECKS != LINEAR_HUMAN_SEMANTIC_READ`

`MACHINE_PASS != HUMAN_SEMANTIC_GATE_PASS`

`PRESENT_AND_HASHED != SEMANTICALLY_READ`

`PROMOTION_REQUIRES_LINEAR_SEMANTIC_READ_WHEN_READABLE`
